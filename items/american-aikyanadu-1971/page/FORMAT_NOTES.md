# PAGE vs ALTO for p017–p019

Master: `p0NN.page.xml` (PAGE 2019-07-15), generated by `json2page.py` from `ocr/p0NN.lines.json`.
Export: `p0NN.alto.xml` (ALTO 4.4, ns-v4), generated by `page2alto.py` from the PAGE files.
Validation: all six files pass lxml XMLSchema checks. PAGE was checked against PRImA `PAGE-release/gts/pagecontent/2019-07-15/pagecontent.xsd` (github PRImA-Research-Lab/PAGE-XML @ d571489), the 2020 git revision 4f40cd4 and the copy bundled with ocrd 3.13.3. ALTO was checked against altoxml/schema `v4/alto-4-4.xsd` and `alto-4-2.xsd` (@ 1a67f01), with the xlink import pointing to a local copy. OCR-D `PageValidator` (strict TextEquiv consistency, coords, baseline) reports 0 errors.

## Why we wrote our own converter
OCR-D `ocrd-page-to-alto` 2.2.12 cannot convert these files as they stand:
- `NoiseRegion` raises `ValueError: Cannot handle PAGE-XML NoiseRegion` (affects p017_r08, p018_r09, p018_r10).
- `TextStyle/@textColour` raises `AttributeError ... 'fontColour'`. This is a bug in `styles.py`, triggered by the blue-ink marginalia lines.

To compare, we patched both problems in a scratch run. The stock output validates against ALTO 4.2, but it has only one `String` per line (31/38/16 Strings in total). It has no ROTATION, BASELINE, ALTERNATIVE or hyphenation, and it uses `LANG="mal"`. It also chains the *unordered* marginalia and map labels into the `IDNEXT` sequence, which gives them a reading order they do not have. `page2alto.py` avoids all of these problems.

## What survived (our ALTO)
| Feature | PAGE | ALTO |
|---|---|---|
| IDs | region/line IDs from lines.json | Same IDs on TextBlock/Illustration/TextLine. Strings are new: `<lineID>_wNNN` |
| Printed text regions | TextRegion @type | TextBlock + `LayoutTag` (`lt_paragraph`, `lt_heading`, `lt_header`, `lt_page-number`, `lt_caption`, `lt_marginalia`, `lt_legend`, `lt_map-label`) |
| Map (p019_r03) | ImageRegion orientation=90 | `Illustration TYPE="map" ROTATION="90"`. It sits inside `ComposedBlock ID="p019_map" TYPE="map"` with the caption, legend and 8 labels. The grouping comes from the PAGE Relations and the map-label tags |
| Rotation (p019: 12 elements) | `@orientation="90"` = rotate 90° clockwise to read | `@ROTATION="90"` = content is rotated 90° counter-clockwise. The number is the same but the sense is stated the other way round |
| Polygons | Coords (all rectangles here) | `Shape/Polygon` on blocks and lines. They are identical because every polygon is a rectangle |
| Baselines | `Baseline` (bottom→top on rotated lines) | `TextLine/@BASELINE` points are copied exactly, so the direction survives |
| Reading order | OrderedGroup: 4 / 6 / 5 refs | `IDNEXT` chain over the same blocks (3 / 5 / 4 links) |
| Line-end word splits (`hyphenEnd`) | custom tag, 16 on p017, 16 on p018 | `SUBS_TYPE=HypPart1/HypPart2` + `SUBS_CONTENT` with the joined word (31 / 33 Strings). The p017_r04_l012 → p018_r03_l001 split is joined across files (`പതിപ്പിച്ചിട്ടുണ്ടു്`). No `HYP` element is written because the print has no hyphen |
| Underline/unclear/damage/inkOver flags | `custom` with exact code-point offsets, plus notes in `@comments` | One `OtherTag` per flag, with the exact span, hand, cert, underline graphic ID and note in `DESCRIPTION`. Every String that overlaps the span carries it in `TAGREFS` |
| Handwritten vs printed | `@production` = printed / handwritten-cursive (Trueman Doctrine, Kennedy.) / handwritten-printscript (CMS, circled 1) | `OtherTag prod_*` on the TextBlock. Blue ink also becomes `TextStyle ts_blue FONTCOLOR=0000FF` |
| Alternative readings | TextEquiv index=2 (Tesseract, conf) on 24 / 34 / 4 lines | `String/ALTERNATIVE` only where the Tesseract token count equals ours: 18 of 24, 21 of 34 and 1 of 4 lines (69 / 72 / 1 ALTERNATIVE elements) |
| Untranscribed map labels (6 on p019) | TextLine with no TextEquiv | `String CONTENT=""` (TextLine needs a String) + `OtherTag not_transcribed`. No text is invented |
| Damage | NoiseRegion | `Illustration TYPE="damage"` + `OtherTag noise`. This is a workaround because ALTO has no noise element |
| Notes | region/line `@comments` | Region notes become `OtherTag <id>_note`. Line notes are kept only inside the flag tags' DESCRIPTION |

## What was lost or flattened
1. **Word geometry is invented.** PAGE stops at line level. ALTO needs Strings, so each line box was split by code-point count along the baseline. On rotated lines the split runs bottom to top. Each such line has `TAGREFS="geom_est"`. Do not use String boxes for precise highlighting.
2. **Flag spans are cut to whole words.** The exact offsets are only in the tag DESCRIPTION; TAGREFS works per String. Five flags do not fall on word boundaries:
   - p017_r04_l002 inkOver 6–23 (starts in the middle of `കാരായിരുന്നതു`)
   - p017_r04_l011 damage 0–1 (the first character `ജ` only)
   - p017_r04_l011 unclear 0–7 (the String also includes the comma)
   - p019_r05_l001 unclear 0–1 (only the digit `6` of `6000`)
   - p019_r15_l001 unclear 7–8 (only the trailing dot of `Kennedy.`)

   In ALTO, each of these marks the whole String.
3. **Unordered groups.** The PAGE UnorderedGroups for marginalia (p017, p019) and map labels (p019) have no ALTO equivalent. Those blocks get no IDNEXT and are simply not in the chain.
4. **Relations.** The 11 / 17 / 2 PAGE `Relation` links have no ALTO element. Examples are an underline graphic → its paragraph, the circled "1" → p017_r04, and damage → the paragraph it affects. Only the caption/legend → map links survive, as the ComposedBlock. Underline graphic IDs survive inside the tag DESCRIPTION.
5. **Alternative readings, partly.** Lines where the token counts differ lose the Tesseract reading completely: 6 on p017, 13 on p018 and 3 on p019, including the junk legend line. The line-level Tesseract `conf` is dropped everywhere. ALTO `WC` describes CONTENT, which is our reading, not Tesseract's, so it is not set.
6. **Semantic types fall back to free text.** `GraphicRegion type="handwritten-annotation"` becomes Illustration `TYPE` (a free string), and `production` becomes a tag. An ALTO consumer that ignores Tags cannot tell handwritten text from printed text. That matters most for p019_r14/r15, which sit next to the printed header.
7. **Region text, script and the IIIF fields.** The region-level TextEquiv, `primaryScript` (Mlym/Latn) and region `continuation` are gone. Only LANG survives (`ml` / `en`; the circled "1" gets no LANG). The IIIF image URL goes to `fileName` and the canvas URI goes to `fileIdentifier`.

## Notes for the rendering stage
- To read text from PAGE, use `TextEquiv[@index="1"]/Unicode`. Index 2 is raw Tesseract output and should be shown only as an alternative.
- PAGE `@orientation="90"` means rotate the crop 90° clockwise to read it upright. ALTO `@ROTATION="90"` describes the same state. Baselines on rotated lines run from the larger y to the smaller y.
- Parse PAGE `@custom` with `(\w+)\s*\{([^}]*)\}` and split on `;` and the first `:`. Offsets are code points, length is end − start. Tags used: `readingOrder{index}`, `underlined{offset;length;hand;cert;graphic}`, `unclear`, `damage`, `inkOver` (all with offset;length;cert), `hyphenEnd{offset;length:0;printed:false}` and `structure{type:legend|map-label|damage}`. Zero-length `unclear{offset:0;length:0}` marks an untranscribed label.
- When joining lines with `hyphenEnd`, add no space. p018_r03 has `continuation="true"`: it continues p017_r04.
- All readings are model-made, not human-verified, as stated in Metadata/Comments and ALTO Processing.
